# Slice 4 Kilo compatibility

Evidence collected September 6, 2026. Real model/authentication/factory acceptance
is **NOT RUN**. The fixture events are source-derived synthetic data, not captured
model output. This document contains no operator executable locations.

| Item                   | Verified contract and limits                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Installation discovery | Local installed native executable reports `7.4.23`; its `run --help` was inspected under an empty environment/private temporary HOME and XDG paths. A separate installed executable reports `7.1.20`, which is not supported. An earlier PATH miss did not establish absence. Target execution-host installation/readiness remains unproven.                                                                                                                             |
| Source pin             | Official `v7.4.23`, commit `40fa10e50a75c4887978d892520d1246515413bf`. Only exact version `7.4.23` is admitted; updates require renewed compatibility evidence.                                                                                                                                                                                                                                                                                                          |
| Host                   | Linux only. macOS managed preference loading has no verified opt-out and is rejected by shared host platform admission. No platform exception for fixtures. Linux subprocess lifecycle acceptance is separate from the local help/parser checks.                                                                                                                                                                                                                         |
| Invocation             | `kilo run --format json --model kilo/<model> --agent build --auto --pure`; prompt is piped to stdin. No continue/session/fork/attach/share flags. Host sets the managed worktree as cwd.                                                                                                                                                                                                                                                                                 |
| Model/auth             | Native Kilo Gateway only, including gateway model IDs containing provider/model. Exactly one selected API key is written as `{"kilo":{"type":"api","key":"…"}}` to the private `XDG_DATA_HOME/kilo/auth.json`. No OpenAI credential dependency. `auth-json` must contain that same single API entry; OAuth, wellknown auth, account metadata, extra providers and custom gateways are rejected. Credential syntax is checked, not online validity or model availability. |
| Private state          | Fresh HOME/XDG/config/cache/state/scratch per attempt. `KILO_TEST_MANAGED_CONFIG_DIR` points inside private HOME. Only selected credential files and declared environment values are handed off; no operator environment, plugin, MCP or global-session discovery. The shared host writes/removes private credentials and preserves cleanup failures.                                                                                                                    |
| Configuration          | `KILO_DISABLE_PROJECT_CONFIG=1`, `KILO_DISABLE_DEFAULT_PLUGINS=1`, `KILO_DISABLE_CLAUDE_CODE=1`, `KILO_DISABLE_EXTERNAL_SKILLS=1`; `--pure` suppresses external plugin origins. Explicit JSON config disables sharing, auto-update, snapshots, LSP and formatters; it allows only provider `kilo`. Models fetch/auto-update/LSP download are disabled; telemetry level is `off`.                                                                                         |
| Legacy configuration   | Project-config disable does **not** suppress the legacy migrators. The shared host rejects the exact legacy paths listed below before launch, including dangling links and unreadable observations. No configuration is deleted.                                                                                                                                                                                                                                         |
| Permissions            | `--auto` approves requests that are not explicitly denied. Workspace-write denies questions/suggestions/interactive-terminal/plan switching. Read-only permits read/glob/grep/list and denies other tools. These are provider policies, **not an OS sandbox**. Host deadlines and output bounds are independent.                                                                                                                                                         |
| Processes              | `KILO_NO_DAEMON=1` disables automatic daemon attachment. The headless command uses its embedded fetch handler without a separately managed `serve` process. Any CLI/tool descendants remain the shared host's responsibility; provider terminal output never proves process death. No legacy Kilo launcher is called.                                                                                                                                                    |
| JSONL                  | `type`, `timestamp`, root `sessionID`, and typed `part` records. The parser binds the root from `step_start`, requires matching part/session/message IDs, permits intermediate `tool-calls` step finishes, and maps final `stop` to provider completion. Other known finish reasons fail closed. `error` maps to failure. Unknown envelopes cannot establish provenance or success. Duplicate/foreign/malformed/contradictory evidence invalidates the stream.           |
| Bounds                 | Parser: 1 MiB line, 16 MiB aggregate, 10,000 events/part IDs, depth 32, one root session, bounded identifiers and credential sizes. Shared host additionally enforces configured stdout/stderr/framing/deadline limits. Truncated final lines fail in the host.                                                                                                                                                                                                          |
| Inspection/recovery    | Bounded `--version` readiness only. No model probe, server, session-list scan, database inspection, conversation resume or replacement. Restart recovery validates signed receipts/heartbeats and authenticated process-group absence, then records conservative supervisor-lost/cancellation outcomes and credential cleanup. It does not replay retained JSONL or reconstruct provider completion. Child session details are unknown.                                  |

The forbidden legacy set is `.kilo/mcp.json`, `.kilocode/mcp.json`,
`.kilo/workflows`, `.kilocode/workflows`, `.kilocodemodes`, `.kilocodeignore`,
`.kilocoderules`, plus `.kilo/rules`, `.kilocode/rules` and those rule-directory
names with each suffix `-code`, `-architect`, `-ask`, `-debug`, `-orchestrator`;
the same five suffixes are forbidden on `.kilocoderules`. This is 24 paths.
Benign `.kilo/skills` remains permitted: Kilo skill discovery uses config
directories, and project/primary-checkout directories are excluded by the
project-config disable flag. External `.agents`/`.claude` discovery is separately
disabled. Default Kilo skills shipped in the pinned binary remain available.

Tool ordering source evidence: tagged [native-runtime.ts](https://github.com/Kilo-Org/kilocode/blob/40fa10e50a75c4887978d892520d1246515413bf/packages/opencode/src/session/llm/native-runtime.ts#L106) dispatches tools into fibers and queues their result events, then concatenates that queue after the provider stream. Thus a provider step finish can precede tool results. The [processor](https://github.com/Kilo-Org/kilocode/blob/40fa10e50a75c4887978d892520d1246515413bf/packages/opencode/src/session/processor.ts#L513) publishes tool settlements independently of its step-finish handler; the headless command forwards both. The parser permits completed/error tool parts for the immediately preceding `tool-calls` message until the next step starts. It retains root/message binding, duplicate detection and terminal fences; late text or foreign messages remain invalid. This is tagged-source evidence and synthetic regression coverage, not a live ordering observation.
